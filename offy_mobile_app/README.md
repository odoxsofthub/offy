# OFFY mobile app: technical reference

OFFY's Android and iOS client is written in Flutter. It talks only to the `/api/mobile/v1` endpoints of the [OFFY Odoo modules](../offy_mobile_connector_odoo), plus Odoo's `/websocket` for live updates.

> End-user setup (Odoo install, enabling users, Firebase console steps) is in the [main README](../README.md). This file is for developers who build, maintain or rebrand the app.

| | |
|---|---|
| Package | `office_app` (Dart) · application ID `com.offy.odox` |
| Flutter / Dart | Flutter 3.44+ stable · Dart `^3.12.0` |
| Platforms | Android (JDK 17, minSdk = Flutter default) · iOS 15.0+ |
| State management | `provider` (`ChangeNotifier`) |
| Dependency injection | `get_it` (`lib/injection_container.dart`) |
| HTTP | `package:http` through a single `ApiClient` |
| Realtime | `web_socket_channel` on Odoo's `/websocket` |
| Firebase | Core, Messaging, Crashlytics, Performance |
| Localisation | `flutter gen-l10n`, 10 languages |

## Getting started

```bash
cd offy_mobile_app

# 1. Firebase config (required, one-time). The generated files are git-ignored.
dart pub global activate flutterfire_cli
flutterfire configure --project=YOUR_FIREBASE_PROJECT_ID

# 2. Dependencies and run
flutter pub get
flutter run
```

A fresh clone **does not compile** until step 1 has created `lib/firebase_options.dart`, `android/app/google-services.json` and `ios/Runner/GoogleService-Info.plist`. On iOS, run `cd ios && pod install` after changing plugins.

### Build-time configuration

Values are read with `String.fromEnvironment` at build time. Every key is optional, and the app runs normally when a key is missing.

| Key | When not set | Purpose |
|---|---|---|
| `API_BASE_URL` | The login screen starts empty | Pre-fills the server URL. A URL the user types always takes precedence |
| `APPCAST_URL` | The update check is **disabled** | URL of the app-update feed ([App update feed](#app-update-feed-appcast)) |
| `API_BEARER_TOKEN` | Not used | Development only. Never set it in a distributed build |

Keep the values in a JSON file and pass it to `flutter`:

```bash
cp env.example.json env.json        # env.json is git-ignored
flutter run --dart-define-from-file=env.json
flutter build appbundle --release --dart-define-from-file=env.json
```

`env.example.json`:

```json
{
  "API_BASE_URL": "https://hr.example.com",
  "APPCAST_URL": "https://raw.githubusercontent.com/YOUR_ORG/YOUR_REPO/main/appcast.xml"
}
```

Individual values can also be passed with `--dart-define=KEY=value`.

### Release builds

```bash
flutter build appbundle --release   # Google Play
flutter build apk --release         # sideload
flutter build ipa --release         # App Store / TestFlight
```

Android `release` builds are signed with the key described in `android/key.properties`. When that file is missing, `android/app/build.gradle.kts` falls back to the debug key, which Google Play does not accept.

```properties
# android/key.properties (git-ignored)
storePassword=<keystore password>
keyPassword=<key password>
keyAlias=upload
storeFile=/absolute/path/to/upload-keystore.jks
```

The keystore and `key.properties` are git-ignored. On iOS, select your Team in Xcode, because no team is set in the project.

## Architecture

The app uses Clean Architecture with MVVM. Each feature follows the same chain:

```
Screen (presentation/screens) ──► Provider (presentation/viewmodels)
        ▲                                   │
        └──── widgets ◄── notifyListeners ──┤
                                            ▼
                         UseCase (domain/usecases)
                                            │
                         Repository interface (domain/repositories)
                                            │
                         RepositoryImpl (data/repositories)
                                            │
                         RemoteDataSource (data/datasources) ──► ApiClient ──► Odoo
                                            │
                         Models / fromJson (data/models) ──► Entities (domain/entities)
```

```
lib/
├── main.dart                 bootstrap: DI, Firebase, Crashlytics hooks, providers, update check
├── injection_container.dart  every data source, repository, use case and provider (get_it)
├── firebase_options.dart     generated by flutterfire, git-ignored
├── core/
│   ├── constants/            api_constants.dart (endpoints, base URL), app_links.dart, assets, error messages
│   ├── network/              ApiClient, ApiResponse, network interceptor, offline wrapper, mock data
│   ├── services/             token storage, session manager, push, realtime sync, app update, observability
│   ├── navigation/           AppRouter: named routes + navigation observer
│   ├── errors/               AppException, ApiErrorHandler
│   ├── theme/                AppColors, AppTheme (light / dark)
│   └── utils/                date formatting, JSON parsing, file download, image compression, payloads
├── data/                     datasources · models · repository implementations
├── domain/                   entities · repository interfaces · use cases
├── presentation/
│   ├── screens/              one folder per feature (home, attendance, time_off, expenses, pay_slip, …)
│   ├── viewmodels/           providers per feature; user/access_provider.dart holds feature flags
│   └── widgets/              shared and per-feature widgets
└── l10n/                     ARB files + generated AppLocalizations
```

### Networking: `core/network/api_client.dart`

- **Base URL:** the URL saved on the login screen (`SharedPreferences` key `saved_login_url`), otherwise `API_BASE_URL`.
- **Headers on every request:** `Authorization: Bearer <access token>` and `X-Mobile-Session: <company session>`. The second one tells the backend which company this device has selected.
- **Token refresh:** a 401 triggers a single shared `POST auth/refresh`, then the original request is retried once. Concurrent 401s wait on the same refresh. A 401 from `auth/login` or `auth/refresh` itself is never retried, because it means the credentials or the refresh token are bad.
- **Errors:** non-2xx replies become `AppException`s via `ApiErrorHandler`, using the backend's `{success, message, code}` envelope.
- **Offline:** `NetworkAwareWrapper` shows an offline screen. The feature list is cached, so the app still starts without a connection.
- **Design mode:** when `AppGlobals.isDesignMode` is true, `MockApiData` answers instead of the server. This is used for UI work and screenshots, and is off by default.

### Authentication and session

`TokenStorage` keeps the access token, refresh token and company session in the iOS Keychain / Android Keystore (`flutter_secure_storage`), and the selected company in `SharedPreferences`. Tokens saved by earlier versions are moved on first launch, so signed-in users stay signed in. Android backup is disabled. The token is only sent to the signed-in server (same scheme, host and port, checked by `ApiConstants.isServerUrl`). `SessionManager.logout()` navigates to login immediately, then revokes the server session and clears local state in the background.

### Feature flags

After login and on every resume, `AccessProvider` loads `GET user/access-details`. Screens, Home cards and navigation call `hasFeature('time_off')` (and similar). The server enforces the same flags with HTTP 403, so hiding a feature in the UI is not the only protection.

### Realtime: `core/services/realtime_sync_service.dart`

1. `POST realtime/ticket` returns a single-use, 60-second ticket.
2. The app connects to `wss://<host>/websocket?ticket=…` with a 30-second ping.
3. Incoming bus frames (`home sections stale`, `access changed`) make the matching providers refetch.
4. Lost connections reconnect with backoff. A fresh ticket is fetched every time.

### Push: `core/services/push_notification_service.dart`

The service starts only when `access-details` reports `push_notifications_enabled`. It asks for permission, registers the FCM token with `POST device-token`, shows foreground messages through `flutter_local_notifications` (Android channel `odox_mobile_default`, icon `@drawable/ic_stat_offy`), and opens the target screen from the message payload.

### App update feed (appcast)

`core/services/app_update_service.dart` reads a [Sparkle](https://sparkle-project.org/documentation/publishing/)-format appcast (parsed by the `upgrader` package) at launch and every time the app resumes. The feed URL comes from `APPCAST_URL`.

**Behaviour**

| Situation | Result |
|---|---|
| `APPCAST_URL` not set, empty or not an `http(s)` URL | No request is made and no update UI is shown. Any previously cached feed is cleared |
| Feed unreachable or not HTTP 200 | The last cached feed (if any) is used; the app continues normally |
| Newest item for the platform is newer than the installed `version+build` | An *update available* sheet is shown on Home; after "later", it is shown again after one day |
| Installed build is lower than the highest item tagged `criticalUpdate` | A full-screen *force update* blocks the app until it is updated |

**Hosting the feed on GitHub**

1. Create a public repository, for example `YOUR_ORG/YOUR_APP-update`, and add `appcast.xml` to the `main` branch.
2. Use the raw file URL as `APPCAST_URL`:
   `https://raw.githubusercontent.com/YOUR_ORG/YOUR_APP-update/main/appcast.xml`
3. Edit and commit `appcast.xml` for each release. GitHub's raw CDN may serve the previous version for a few minutes after a commit.

Any HTTPS location that returns the file works equally well.

**Feed format**

One `<item>` per release and platform. `sparkle:version` uses the same `version+build` format as `pubspec.yaml`, and `<enclosure url>` is the store page opened by "Update".

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <title>App updates</title>

    <item>
      <title>Version 1.0.1 (2)</title>
      <description>
        - First change
        - Second change
      </description>
      <pubDate>Mon, 12 Oct 2026 10:00:00 +0000</pubDate>
      <sparkle:version>1.0.1+2</sparkle:version>
      <enclosure url="https://play.google.com/store/apps/details?id=YOUR.APP.ID" sparkle:os="android" />
    </item>

    <item>
      <title>Version 1.0.1 (2)</title>
      <description>
        - First change
      </description>
      <pubDate>Mon, 12 Oct 2026 10:00:00 +0000</pubDate>
      <sparkle:version>1.0.1+2</sparkle:version>
      <enclosure url="https://apps.apple.com/app/idYOUR_APP_ID" sparkle:os="ios" />
      <!-- Force update: everyone below 1.0.1+2 must update -->
      <sparkle:tags><sparkle:criticalUpdate/></sparkle:tags>
    </item>
  </channel>
</rss>
```

- `<description>`: release notes, one point per line.
- `<sparkle:tags><sparkle:criticalUpdate/></sparkle:tags>`: makes that item the minimum supported build.
- Optional `<sparkle:minimumSystemVersion>`: the lowest OS version that should see the item.
- Add an item only after the build is live in the store, so users are never sent to a version they cannot download.

## Adding a feature

1. **Endpoint:** add the path to `core/constants/api_constants.dart`.
2. **Data:** add a model (`fromJson` using `api_parser_utils.dart` for safe casts), a data source method that calls `ApiClient`, and a repository implementation.
3. **Domain:** add an entity, a repository interface and a use case.
4. **Presentation:** add a provider (`ChangeNotifier`) with loading, empty and error states, plus the screen and its widgets.
5. **Wire up:** register everything in `injection_container.dart`, add a route in `core/navigation/app_router.dart`, and gate it with `hasFeature('<code>')` if the backend has a feature code for it.
6. **Strings:** add them to `lib/l10n/app_en.arb` and the other ARB files. They are generated on build.

## Localisation

ARB files live in `lib/l10n/` (`l10n.yaml`, template `app_en.arb`). The shipped languages are en, ar, de, es, fr, hi, ja, pt, zh and zh_TW. `ml` exists but is not in the picker. To add a language, create `app_xx.arb`, run `flutter gen-l10n` (or simply build), and add it to `presentation/screens/language/language_page.dart`. Missing keys are listed in `untranslated_messages.json`.
